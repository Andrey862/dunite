# Спецификация: высокопроизводительный клон Obsidian на Rust + gpui

**Статус:** черновик v0.1
**Дата:** 2026-10-20
**Название проекта:** **dunite** (дюнит — магматическая порода, в пару к обсидиану; префикс крейтов `dunite-*`)

---

## 1. Видение

Локальное десктопное приложение для ведения связанных заметок (personal knowledge management) поверх обычной папки с markdown-файлами. Ключевые отличия от Obsidian:

- **Нативность и скорость.** Rust + gpui (GPU-рендеринг, тот же UI-фреймворк, что в Zed IDE). Никакого Electron, Chromium, DOM и JS. Цель — мгновенный отклик на ввод, холодный старт < 300 мс, работа с хранилищами в десятки тысяч заметок без просадок.
- **Plain markdown.** Хранилище — просто папка. Мы не вводим проприетарных форматов; всё, что мы пишем, читается любым редактором и `git diff`-ится построчно.
- **Git как первоклассный механизм бэкапа.** Автоматические снапшоты, таймлайн истории, восстановление любой заметки или всего хранилища.

|---|-------|-------------|

## 3. Не-цели (v1)

Осознанно **не делаем** (может появиться позже, но не влияет на архитектуру v1):

- Система плагинов и скриптовая песочница.
- Публикация заметок в веб (аналог Obsidian Publish).
- Canvas / доски.
- Мобильные платформы, веб-версия.
- Облачная синхронизация своим протоколом (синхронизация = git remote, это ответ пользователя).
- Сквозное шифрование хранилища.
- Вид графа связей (graph view) — вероятный кандидат в v2, модель данных его не блокирует.
- Просмотр PDF-вложений — за пределами MVP.
- Экспорт в HTML/PDF — за пределами MVP.
- Пользовательские темы (кастомизация цветов из TOML) — за пределами MVP; в MVP только встроенные light/dark.
- Явный режим «чистый source-редактор» с отключёнными декорациями — будет, но после стабилизации Live Preview.

## 4. Ключевые архитектурные решения

Зафиксированы на этапе спецификации:

| Решение | Выбор | Обоснование |
|---------|-------|-------------|
| Формат редактора | **Live Preview** (а-ля Obsidian) | Обратимость: файл на диске всегда валидный markdown. Совместимость с git/другими инструментами. |
| Текстовый движок | **Своя реализация на gpui + ropey** | Полный контроль над блочным рендерингом и декорациями; нет зависимости от внутренних крейтов Zed и их частых API-переломок. |
| Платформы | **Linux first** (Wayland/X11), macOS/Windows позже | Среда разработки — Linux; gpui официально поддерживает Linux через blade. |
| Язык документации | **Русский**, термины и идентификаторы — английский | |

## 5. Стек технологий

| Область | Технология | Примечание |
|---------|-----------|------------|
| UI | `gpui` (crates.io, версия 0.2.x, пиннить) | Zed's GPU-у accelerated UI framework |
| Текстовый буфер | `ropey` | Rope-структура, O(log n) вставки/удаления |
| Markdown | `pulldown-cmark` (CommonMark + GFM) + собственный сканер inline-расширений | `into_offset_iter()` даёт диапазоны блоков для декораций; `[[wikilinks]]`, `#tags`, `![[embeds]]` — поверх, своим сканером |
| Frontmatter | `serde_yml` (YAML) | Теги, алиасы, title, cssclass |
| Полнотекстовый индекс | `tantivy` | BM25, инкрементальные апдейты документов |
| Фаззи-поиск файлов | собственный скоринг (или `nucleo-matcher`) | Quick switcher по путям и заголовкам |
| Слежение за ФС | `notify` + debounce | Инкрементальная переиндексация |
| Git | `git2` (libgit2) | status/commit/diff/log/restore без shelling out |
| Изображения | `image` (decode) + gpui image cache | |
| Логирование | `tracing` + `tracing-subscriber` | |
| Конфигурация | `serde` + TOML | см. §12 |

Внешних runtime-зависимостей нет (кроме системных библиотек для Wayland/X11/шрифтов).

## 6. Архитектура: workspace

Cargo workspace, жёсткое разделение слоёв — UI не знает про файловую систему напрямую:

```
crates/
  dunite-app/          # точка входа: инициализация, окно, wiring всех подсистем
  dunite-ui/           # gpui-компоненты: дерево, табы, сплиты, палитры, сайдбары
  dunite-editor/       # буфер (ropey), layout строк, курсоры/выделения, undo, ввод,
                        # декорации Live Preview, inline-рендер изображений
  dunite-markdown/     # парсинг markdown → блоки/инлайны, расширения (wikilink, tag,
                        # embed), позиционные маппинги, сериализация
  dunite-vault/        # модель хранилища: заметки, frontmatter, вложения, резолвинг
                        # ссылок, файловые операции, watcher
  dunite-index/        # граф ссылок/тегов (in-memory) + tantivy full-text индекс
  dunite-git/          # снапшоты, история, diff, восстановление
  dunite-settings/     # глобальные и per-vault настройки, темы
```

Правила зависимостей (проверяются на CI простым grep по Cargo.toml):

```
app → ui, editor, vault, index, git, settings
ui  → editor, vault, index, git, settings      (только типы и запросы, не ФС)
editor → markdown, vault                       (только типы: NoteId, LinkTarget)
index  → vault, markdown
git    → vault
vault  → markdown
```

Всё взаимодействие между слоями — через типы данных (`NoteId`, `NoteMeta`, `Backlink`, `SearchHit`...), никаких «общих» глобалов. Тяжёлая работа (парсинг, индексация, git-операции, декодирование картинок) выполняется в background-потоках, результат доставляется в UI через `AsyncAppContext` / каналы событий gpui.

## 7. Доменная модель хранилища (vault)

Vault = директория с markdown-файлами. Никакой БД, состояние выводится из файлов и держится в памяти.

### 7.1 Сущности

```rust
struct Vault {
    root: PathBuf,
    notes: HashMap<NoteId, NoteMeta>,   // NoteId = относительный путь
    attachments: HashMap<AttachId, AttachmentMeta>,
    graph: LinkGraph,                   // ссылки, backlinks, теги (in-memory)
}

struct NoteMeta {
    id: NoteId,                 // "projects/alpha.md"
    title: String,              // frontmatter.title или имя файла
    aliases: Vec<String>,
    tags: Vec<Tag>,             // из frontmatter + inline #tags
    links_out: Vec<OutLink>,    // [[target]] + позиция + resolved?
    headings: Vec<Heading>,     // для outline и навигации
    frontmatter: Option<serde_yml::Value>,
    mtime: SystemTime,
    size: u64,
}

struct OutLink { target: LinkTarget, display: Option<String>, range: Range<usize>, kind: LinkKind }
enum LinkKind { Wiki, Markdown, Embed, BlockRef /* v2 */ }
```

### 7.2 Идентичность и резолвинг ссылок

- `[[Projects/Alpha]]` — путь без расширения; `[[Alpha]]` — короткое имя, резолвится по правилам Obsidian:
  1. точное совпадение относительного пути к текущей заметке;
  2. уникальный суффикс пути;
  3. алиас из frontmatter;
  4. иначе — **unresolved link** (серый стиль, создаётся по клику с выбором расположения).
- Пересохранение ссылок при переименовании файла — **обязательно** (обновлять все `[[...]]`, указывающие на файл). Операция атомарная через temp+rename.
- Markdown-ссылки `[text](path.md)` резолвятся по пути; внешние URL открываются системным браузером.

### 7.3 Frontmatter

YAML-блок в начале файла. Читаются: `title`, `aliases`, `tags`, `cssclass`. Неизвестные ключи сохраняются нетронутыми при любом редактировании (round-trip гарантируется: мы редактируем только изменённые диапазоны текста).

### 7.4 Теги

- Inline: `#tag`, `#tag/subtag` — вне код-блоков и inline-кода, после символа-разделителя.
- Frontmatter: `tags: [a, b]` / `tags: a\n  b`.
- Теги регистронезависимы, хранятся в lowercase.

### 7.5 Вложения (изображения)

- Форматы v1: PNG, JPEG, GIF (статичный первый кадр), WebP, SVG.
- Папка вложений: настройка (по умолчанию корень vault), читается из `.obsidian/app.json` → `attachmentFolderPath` при открытии чужого vault'а.
- Резолвинг `![[img.png]]` — по тем же правилам, что и ссылки на заметки.

### 7.6 Совместимость с хранилищами Obsidian

- Открываем существующий vault Obsidian как есть: те же `.md`, те же `[[wikilinks]]`, те же вложения.
- Читаем (только) из `.obsidian/`: папку вложений. Настройки тем/плагинов игнорируем.
- Пишем свои настройки в `.dunite/` внутри vault'а (см. §12), **не трогая** `.obsidian/`.
- Наши файлы индекса/кэша не попадают в git-снапшоты (`.gitignore`-фильтры).

## 8. Редактор (Live Preview) — ядро спецификации

### 8.1 Текстовая модель

- Буфер — `ropey::Rope`; координаты редактирования — byte/char offset'ы; для UI — (row, column).
- `EditorBuffer` хранит: rope, undo-историю, опции (tab size, word wrap), и **версию** (`u64`), инкрементируемую при каждом изменении.
- Undo/redo — операции (insert/delete) с группировкой по времени (< 500 мс — одна группа) и по действиям (авто-продолжение списка — одна группа с вводом). Поддерживаются «точки сохранения» для git-снапшотов.
- Курсор: v1 — один курсор + выделение; мультикурсор — v1.1 (модель с самого начала: `Vec<Cursor>`, все операции векторизованы).

### 8.2 Парсинг и декорации

Парсим markdown **инкрементально по блокам**:

1. При изменении буфера находим границы изменённого блока (по blank-line-разделителям), репарсим только его ± один блок соседей.
2. Блоки — это единица layout: каждый блок рендерится как `gpui::Element`-подобная строка(и) с собственной типографикой.
3. Инлайны внутри блока парсятся позиционным сканером поверх текста: emphasis, code spans, links, wikilinks, tags, embeds, escaping.

**Декорации (что видит пользователь):**

| Элемент | Рендер |
|---------|--------|
| `# H1` … `###### H6` | Увеличенный/жирный шрифт, `#`-префикс **скрыт** (conceal), пока курсор не в блоке |
| `**bold**`, `*italic*`, `~~strike~~`, `` `code` `` | Стилизация текста, маркеры скрыты вне фокуса курсора |
| `[[link]]` | Стилизованная ссылка; клик → переход; Ctrl+клик — в новой вкладке; unresolved — серый |
| `![[img.png]]`, `![](img.png)` | **Inline-изображение** в строке (масштабируется по ширине, с ограничением высоты), клик → открыть в превью |
| `-` / `1.` списки | Маркер рисуется декорацией (нумерация — авто), Tab/Shift+Tab меняют уровень |
| `* [ ]` / `- [x]` task lists | Кликабельный чекбокс вместо маркера, `[ ]`/`[x]` скрыты; клик переключает состояние |
| `> ` quote | Вертикальная линия + приглушённый текст, префикс скрыт |
| ```` ```code block` ```` | Блок с моноширинным шрифтом и фоном, подсветка синтаксиса — v1.1 (tree-sitter), в v1 — plain |
| `---` | Горизонтальная линия во всю ширину |
| `^blockid` | Скрыт, если курсор не в блоке |
| Frontmatter | Сворачиваемая серая плашка вверху |

**Concealment-правило:** синтаксические маркеры показываются только в блоке, где стоит курсор (или в выделении). Это ключ к ощущению WYSIWYG при полностью обратимом markdown.

### 8.3 Ввод и навигация

- Полный набор: стрелки/Home/End/PageUp/Down, Ctrl+стрелки (слово), Shift-выделение, Ctrl+A/C/X/V, мышь (клик, двойной клик — слово, тройной — строка, drag).
- Клик по декорированному элементу: ссылка — переход, изображение — превью, чекбокс task list — переключение `[ ]` ↔ `[x]`.
- Авто-продолжение: Enter в списке/цитате продолжает их; в пустом пункте — выход из списка. `**bold**`-обёртка выделения, `` `code` ``-обёртка.
- Клавиатура: `Ctrl+B/I/K` (bold/italic/link), `Tab`/`Shift+Tab` (уровень списка), `Ctrl+Enter` (перейти по ссылке под курсором), `Alt+←/→` (навигация back/forward по посещённым заметкам).
- Клипборд: текст + вставка файлов изображений (копирование в папку вложений + вставка `![[...]]`).
- IME (ввод CJK/русской раскладки) — через штатный ввод gpui; проверка на Linux обязательна.
- Выделение текста мышью за пределами окна — авто-скролл.

### 8.4 Layout и производительность рендера

- Виртуализация строк: рендерим только видимую область + буфер 2 экрана.
- Измерение строк кэшируется по (версия буфера, ширина, font settings).
- Бюджет кадра при наборе: **< 8 мс** (включая репарсинг блока и repaint), при скролле 60 fps на хранилище из 10k заметок.
- Скроллбар с «миникартой» пропорции документа (v1.1).

### 9.1 Левая панель

- **Переключатель хранилищ** (`Vault ▾`): список недавних, «Открыть папку…», «Создать хранилище…».
- **Дерево файлов:** ленивое (раскрывается по требованию), сортировка (папки/файлы, по имени, опционально — по mtime), контекстное меню (новая заметка/папка, переименовать F2, удалить, копировать путь), drag & drop (перемещение с обновлением ссылающихся ссылок), inline-переименование, иконки по типу, badge для непрочитанных (v2).
- **Панель поиска** (см. §11).

### 9.2 Вкладки и сплиты

- Табы с закрытием (колёсико мыши), reorder drag'ом, «закрыть другие/все справа», pinned tabs (v1.1).
- Сплиты: горизонтальный/вертикальный (`Ctrl+\`), перетаскивание таба между сплитами, фокус между сплитами (`Ctrl+1..9` / `Ctrl+Alt+←/→`).
- Состояние вкладок восстанавливается при перезапуске (per-vault).
- `Ctrl+W` — закрыть вкладку с подтверждением, если есть несохранённые изменения (автосейв делает это редким).

### 9.3 Правая панель (сайдбар)

- **Outline** — заголовки текущей заметки, клик — переход.
- **Backlinks** — список заметок, ссылающихся на текущую, с фрагментом контекста и счётчиком; клик — переход к позиции; секция «Unresolved» для битых ссылок на эту заметку.
- **Теги** — все теги хранилища с числом заметок; клик — фильтр в поиске; иерархия `a/b`.
- **Git timeline** (см. §10).

### 9.4 Команды и палитры

- `Ctrl+P` — quick switcher: фаззи-поиск по путям и заголовкам заметок (MVP — самая важная навигация).
- `Ctrl+Shift+P` — command palette: все действия приложения, фаззи по названию.
- `Ctrl+Shift+F` — глобальный поиск по хранилищу.
- `Ctrl+G` — переход к строке (v1.1).
- Все действия в палитре имеют бинды; бинды показываются в палитре; keymap — в настройках (v1.1: редактирование, v1: чтение из TOML).

### 9.5 Статус-бар

Позиция курсора, счётчик слов/символов, состояние git (число изменённых файлов, последний снапшот), состояние индекса, индикатор внешних изменений файла («файл изменён снаружи — перечитать?» при конфликте с буфером).

## 10. Git-бэкапы (F9)

Философия: **git — это и есть бэкап**, без второй системы версий.

### 10.1 Поведение

- При открытии хранилища проверяем наличие git-репозитория; если нет — предлагаем `git init` (одна кнопка) с базовым `.gitignore` (`.dunite/`, `.obsidian/`, `.DS_Store`, `Thumbs.db`).
- **Автоснапшоты:** debounce 60 с после последнего изменения (настраивается), либо по явной команде `Ctrl+S` → `Snapshot now`. Коммит создаётся с сообщением `snapshot: YYYY-MM-DD HH:MM · N notes changed` и автором `dunite <dunite@local>`.
- Снапшоты коммитятся в **текущую ветку** (не создаём скрытых веток — пользователь должен видеть историю обычным `git log`). Опция `snapshot_branch` (v1.1) для желающих изолировать.
- Наши коммиты **не пушат** ничего сами; `Push/Pull` — ручные команды в панели git (v1.1; v1 — только локальные снапшоты).
- Всегда коммитим только рабочее дерево; никогда не делаем `reset --hard`, не удаляем файлы без явного действия пользователя.

### 10.2 UI панели «Git timeline»

- Список коммитов (для текущей заметки / для всего хранилища — переключатель).
- Клик по коммиту → **diff-превью** (построчный +/-, read-only) и кнопки: `Восстановить заметку`, `Сохранить копию как…`, `Показать в файловом дереве`.
- Восстановление = ещё один коммит (никакой потери истории), конфликт с открытым буфером решается через показ диалога «перечитать/оставить».
- Статус-бар показывает dirty-состояние (вкладка с модифицированной заметкой помечается точкой).

### 10.3 Семантика автосейва

Редактор пишет файл на диск по debounce 500 мс после последнего изменения (атомарно: temp + rename). Git-снапшот — отдельный, более редкий слой. Это даёт: живую синхронизацию с внешними инструментами + аккуратную историю без коммита на каждое нажатие клавиши.

## 11. Поиск и индексация (F7)

### 11.1 Два уровня поиска

1. **Quick switcher** (`Ctrl+P`) — фаззи по путям + заголовкам, результат < 10 мс, без индекса (по in-memory списку).
2. **Полнотекстовый поиск** (`Ctrl+Shift+F`) — tantivy-индекс по всем заметкам.

### 11.2 Индекс

- Путь: `.dunite/index/` внутри vault (или XDG cache по хешу корня — настройка). Не коммитится.
- Документ = заметка: поля `path`, `title`, `body`, `tags`, `links`, `aliases`.
- Токенизация: юникод-aware, lowercase; код-блоки индексируются (Obsidian тоже) — опция отключения.
- **Инкрементальность:** watcher события → debounce 300 мс → переиндексация изменённых файлов → событие в UI. Полная пересборка — при изменении версии схемы или по команде.
- Стартовая индексация: background, прогресс в статус-баре, параллельность = число ядер.

### 11.3 Язык запросов

```
встречаемый текст              → BM25 по body/title
"точная фраза"                 → phrase query
tag:work  path:projects/       → фильтры (комбинируются с текстом)
link:[[Alpha]]                 → заметки, ссылающиеся на Alpha
file:.md                       → расширение (v1.1)
```

Результаты: список с highlighted-фрагментами (до 3 совпадений на заметку), сортировка по релевантности / пути / mtime, клик — переход к позиции. Горячие клавиши навигации по результатам (`↑↓`, `Enter` — открыть, `Alt+Enter` — в новой вкладке).

## 12. Настройки и темы

- **Глобальные:** `~/.config/dunite/settings.toml` — тема, шрифты (UI/monospace), горячие клавиши, список хранилищ, настройки git-снапшотов, поведение редактора.
- **Per-vault:** `.dunite/config.toml` — папка вложений, формат ссылок (wikilink/markdown) при создании, exclusions для индекса и git.
- Темы: ровно **две встроенные — light и dark**, авто-выбор по системной теме (штатные средства gpui). Кастомные темы и переопределение цветов из TOML — за пределами MVP.
- Все настройки имеют дефолты; отсутствие файлов — валидное состояние.

## 14. Обработка edge cases (частично)

- Файл изменён снаружи, пока открыт в буфере без правок → молча перечитать; с правками → диалог (перезаписать/перечитать/сохранить копию).
- Файл удалён снаружи, открыт в табе → таб помечается «(deleted)», не теряем содержимое буфера.
- Переименование в дереве при открытых вкладках → обновлять ссылки + переносить буферы.
- Невалидный YAML frontmatter → не падать, показать как текст, правки не терять.
- Огромные файлы (> 5 МБ markdown) → открыть, но без Live Preview (plain-режим) и без индексации по умолчанию.
- Символические ссылки, пути с юникодом/пробелами — поддержаны; пути нормализуются.
- Конфликт git-merge при pull (v1.1) → показать конфликтные файлы, не пытаться магически резолвить.

## 15. Стратегия тестирования

- **Юнит:** `dunite-markdown` (парсинг/позиции/round-trip), `dunite-vault` (резолвинг ссылок, переименование), `dunite-editor` (операции над буфером, undo, обёртки выделения).
- **Свойство:** round-trip «отредактировать → сериализовать → парсится обратно без потерь» (`proptest`).
- **Интеграция:** инкрементальная индексация на fixture-хранилище (1k сгенерированных заметок), git-снапшоты во временном репозитории.
- **e2e (smoke):** gpui test context — открыть vault, открыть заметку, набрать текст, сделать снапшот. Небольшой набор, прогон на CI (headless).
- **Fixtures:** `testdata/vault-small` (реалистичное хранилище с edge cases), `vault-gen` (генератор 10k заметок для бенчей).

## 17. Риски

| Риск | Влияние | Митигация |
|------|---------|-----------|
| API gpui нестабильно (молодой публичный крейт) | среднее | Пиннить версию; обёртка `dunite-ui` изолирует API-изменения |
| Сложность собственного текстового движка (layout строк, IME, скролл) | высокое | M1 выделен отдельно; критические пути покрыты юнитами; вдохновляться архитектурой Zed, но не тащить код |
| Инкрементальный парсинг markdown даёт артефакты при быстром наборе | среднее | Репарсинг блоками + дебаунс; fallback — полный репарс блока |
| Round-trip markdown: случайная порча файла | высокое | Правки только точечными диапазонами; proptest-свойства; git-снапшоты как страховка |
| Производительность tantivy на больших vault'ах | низкое | Бенчи на 10k/50k с M4 |
| libgit2 поведение отличается от git CLI | низкое | Не делать опасных операций; интеграционные тесты |
| Одиночный разработчик + vibe coding → дрейф архитектуры | среднее | Этот документ как контракт; workspace-границы проверяются на CI |
