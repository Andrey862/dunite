# Бенчи и бюджеты производительности

Замеры от **2026-10-25**, машина разработки (Linux, Intel UHD TGL, 4 ядра).
Как воспроизвести:

```sh
cargo bench                      # criterion-бенчи ядра
scripts/bench_runtime.sh 50      # холодный старт
scripts/bench_runtime.sh 10000   # открытие большого хранилища + память
```

## Замечания

**Память (327 МБ на 10k).** Бюджет §13 «< 200 МБ (без индекса)» писался
под tantivy с индексом на диске; по решению §18 индекс стал in-memory
(общий конвейер разбора с графом), поэтому бюджет пересмотрен:
**< 400 МБ RSS на 10k** (измерено 327 МБ, из них ~73 МБ — база gpui/Vulkan
приложения, ~254 МБ — граф+постинги+метаданные, ~25 КБ/заметку).
Резерв оптимизации: интернирование `NoteId` в постингах (сейчас каждая
запись хранит клон строки) — ожидаемое снижение ~30–50%.

**Скролл 60 fps** — графический бюджет, замеряется вручную в живом UI
(бюджет §13 выполняется: виртуализация строк, рендер только видимых).

**Quick switcher < 10 мс** — отдельно не мерялся; путь поиска — тот же
фаззи-скан, что и в M3 (O(число заметок) без аллокаций строк) — оценочно
единицы мс на 10k.

**Индексация в фоне** — бюджет §13 подразумевал фоновую индексацию;
сейчас граф строится на старте (850 мс на 10k — укладывается в бюджет
открытия), перенос в фон — задача оптимизации после MVP.
